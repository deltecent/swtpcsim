# `reference/` — distilled hardware references

These `.md` files are **ours**: text-only emulation references, each written *from* a period
scan (a vendor data sheet or a MITS manual) and each citing that scan by filename in a `Source:`
line at its top. They carry what a developer reopens the scan for — register maps, port
addresses, status/control bit tables, disk geometry and timing, boot sequences, and the quirks
that bite an implementer.

The **scans themselves are not redistributed** (they are large and not ours; see
`.gitignore`). `docs/sources.md` is the manifest — what each original source is, where it came
from, and the traps paid for once. Read it before trusting any single number here; several of
these sources contradict themselves, and `sources.md` records which reading won and why.

The `Source:` links point at `#` — a placeholder to be filled in with a real URL later.

|---|---|
| [Motorola M6800 Programming Reference Manual](Motorola%20M6800%20Programming%20Reference%20Manual.md) | The canonical **MC6800** CPU reference (M68PRM(D), Nov 1976): the programmer's register/flag model, the seven addressing modes, and the **complete 72-mnemonic / 197-opcode** instruction set with per-opcode addressing mode, byte count, machine-cycle count, and H·I·N·Z·V·C flag effect, plus the stack/interrupt/reset model an emulator core needs. The opcode-level authority the 680b Programming Manual deliberately defers to. |
| [Motorola MC6809 / MC6809E Programming Manual](Motorola%20MC6809-MC6809E%20Programming%20Manual.md) | The canonical **MC6809/MC6809E** CPU reference (M6809PM(AD), 1981): the register/flag model, every addressing mode with its exact index post-byte encoding and extra-cycle/byte costs, the complete instruction set with opcodes (including the page-2 `$10` and page-3 `$11` prefixes), byte/cycle counts and flag effects, the interrupt/stacking model, and the 6809-vs-6809E and 6809-vs-6800 differences. |
| [M6800 "NOP before SEI" erratum](6800%20NOP%20before%20SEI.md) | The early-mask MC6800 quirk (parts made before November 1977): `CLI`/`SEI` take effect reliably only when the **preceding instruction has an odd opcode**, so period code opening an interrupt window under program control uses **`CLI`-`NOP`-`SEI`** rather than `CLI`-`SEI`. Why a lone `NOP` before `SEI` is a precaution and not dead code — and the note that swtpcsim models the corrected mask, so the quirk is deliberately **not** reproduced. |

## Altair 680 (Motorola 6800)

MITS's *second* machine — a **6800** computer, not an 8080/S-100 system, so its boards are
**memory mapped** (no `IN`/`OUT`) and generally **active-low**. Grouped here so the 6800 parts
are not mistaken for S-100 hardware.

| Reference | What it covers |
|---|---|
| [Altair 680b KCACR](Altair%20680b%20KCACR.md) | The 680b's Kansas City Standard audio-cassette interface — a **memory-mapped** board (not `IN`/`OUT`): status/control at **`F010`** (61456), read/write data at **`F011`**, read-vs-write of each address being different registers. Documents the **⚠ active-low ("True = Logic 0")** status/control convention (status D0 Read-Data-Available / D7 Transmit-Buffer-Empty; control D0/D1 read/write interrupt enable, D6/D7 remote motor off/on), **software motor control** (store `7F` on / `BF` off; `POKE 61456,127`/`191`), the interrupt model (enable via `FE`/`FD`; `IRQ` vector `FFF8/FFF9` → `0100` from the monitor PROM; any register access or Motor-Off clears the latch), the **SMC COM2017/H** UART (same 1602 family as [com2502](com2502.md), 8N2, 4800 Hz 16× clock), the **Kansas City Standard** modulation (300 baud; mark = 8×2400 Hz, space = 4×1200 Hz; LSB first) and the loader/punch PROM (socket V, **`FD00`**; punch `.J FD74`, load `.J FD00`; Motorola S-records; `C`/`M` error characters). |
| [Altair 680b Universal I/O Board](Altair%20680b%20Universal%20IO%20Board.md) | The 680b's general-purpose parallel+serial expansion board — **memory-mapped**, one slot, built from a **6820 PIA** (parallel) and a **6850 ACIA** (serial). Documents the `F0XX` address model (A15–A8 = `F0`, A7–A4 via switch **S9**, A3 parallel/serial, A2 parallel-port select) and the **default map** (PIA-C parallel `F008`–`F00B`, PIA-B `F00C`–`F00F`, ACIA-D serial `F006`/`F007`); the **fixed** switch-input port at **`F003`** and the 8-bit non-latched output at **`F010`–`F013`** (⚠ **collides with the KCACR** — period fix is "remove UI/O IC A1"); the standard 6820 PIA model (A/B sections, Control bit 2 = DDR/Data select, CA1/CA2/CB1/CB2 handshake, power-on reset → all inputs); the standard 6850 ACIA control/status bits (master-reset `11`, ÷16/÷64, RDRF/TDRE/DCD/CTS/FE/OVRN/PE/IRQ); baud via switch **S10** + clock-divide (75–9600, or 5 extra ÷64 rates); RS-232/TTL/20 mA-TTY levels; and both chips' `IRQ` wiring (active-low → `FFF8/FFF9` → `0100`). **⚠ active-HIGH** (raw Motorola bits — *not* the KCACR's inverted-true rule). |
| [Altair 680b Operator's Manual](Altair%20680b%20Operators%20Manual.md) | The operator-facing guide to the **680b machine itself** (not a plug-in board) — the three user-wired areas of the **main PC board** and, most useful for emulation, **front-panel operation** and the **power-up/deposit sequence**. Documents the baud-rate generator jumper truth table (4 holes → 50–9600 baud at IC Z pin 10; ⚠ **2400 listed twice**, reproduce verbatim); the **1 K on-board RAM** base-address scheme (jumpers 1–6 / pads 10–15 = NAND of A10–A15 or complements; worked bases `0000`, `2000`/8 K, `4000`/16 K, `5000`/20 K, `6000`/24 K, `8000`/32 K); the three **hardware-programmable bits** (1 = Baudot yes/no, 2 = 1/2 stop bits, 5 = No-Terminal/Terminal; 3,4 reserved, tie LOW); the three serial **interface builds** (ASR33/KSR33 20 mA loop, RS-232, Baudot-needs-external-isolation); the optional **PTRC** paper-tape-reader-control block; the **front panel** (4-hex-digit address A0–A15, 2-hex-digit data D0–D7, down=0/up=1, HALT continuously addresses the switches, DEPOSIT, RESET-before-RUN, "AC" power LED); and the **power-up sequence** (HALT→POWER→RESET→ADDRESS/DATA→DEPOSIT; the **No-Terminal bit** makes the PC start at `0000` on RUN; with a terminal, defer to the System Monitor manual). |
| [Altair 680b Programming Manual](Altair%20680b%20Programming%20Manual.md) | The programmer's guide to the **680b** (Motorola **6800**) — mostly the standard Motorola M6800 reprint (CPU model, 7 addressing modes, 72-mnemonic/197-opcode set, arithmetic tutorials, **all deliberately out of scope** here — see the [Motorola M6800 Programming Reference Manual](Motorola%20M6800%20Programming%20Reference%20Manual.md) for that), distilled down to what is **680b-specific**. Documents the **programming model** (ACCA/ACCB/IX/PC/SP, 6-bit CCR `H I N Z V C`); the **addressing-mode summary** (byte counts; ⚠ CPX/LDS/LDX take 3-byte immediates; ⚠ **direct-vs-extended chosen by value** — ≤255 direct, >255 extended; branch range `(PC+2)−128…+127`, 8-bit two's-comp offset); the **interrupt latency** (⚠ **12 cycles** from end of instruction, **4** after `WAI`); the **680b assembler source language** (number formats — default decimal, `$`/`H` hex, `@`/`O`/`Q` octal, `%`/`B` binary, `#'C` ASCII; ⚠ `$…B` = hex; one-level forward reference; no operator precedence) and directives (incl. the 680b-specific **`MON`** = return to PROM Monitor); and — the emulation payload, from **Appendix C** — the full **6850 ACIA** register model (TDR/RDR + write-only Control + read-only Status): Control CR1,0 divide (`11`=Master Reset), CR4–2 word/parity/stop (unbuffered), CR6,5 Tx-ctrl+RTS+break, CR7 Rx-int-enable; Status RDRF/TDRE/DCD/CTS/FE/OVRN/PE/IRQ with ⚠ **CTS-high inhibits TDRE** and **DCD-high forces RDRF empty**; ⚠ **ACIA is not auto-reset on power-on** (software must Master-Reset then set divide); the **paper-tape reader** control (RTS high, CR6=1/CR5=0, = reader ON); and the **interrupt vectors** at `FFF8`–`FFFF` in the PROM Monitor (IRQ `FFF8/9`→`0100`). ⚠ **The ACIA's memory address is not given here** — it comes from the machine wiring (KCACR `F010`/`F011`, UI/O S9 window); do not invent one. |
| [Altair 680b Theory of Operation](Altair%20680b%20Theory%20of%20Operation.md) | The circuit-level companion to the Operator's and Programming manuals — and the one that **names the on-board addresses the Programming Manual withheld**. Documents the **680b clock** (500 KHz two-phase non-overlapping, 2 MHz crystal ÷4; Φ1 hi 600 ns/lo 1.4 µs, Φ2 hi 1 µs; ⚠ **all transfers on Φ2**, and the 6800 runs at **½ speed vs stock**); the full **6800 bus-control signal set** (`RESET`→PC from `FFFE/FFFF`; `HALT` hi=RUN, lo=halted→`BA` hi→buses tri-stated→front panel; `R/W` hi=READ; `VMA`; `DBE`=Φ2; `R/W-P`=R/W∧Φ2; `BA`; `TSC`=DMA); the memory/PROM map (**1 K** 2102A RAM jumper-placed; four 256×8 PROMs, **PROM 1 at `FF00`** → monitor+vectors in `FC00`–`FFFF`); and — the emulation payload — the **on-board address decode**: the **serial 6850 ACIA at `F000`/`F001`** (`F000`=Control(W)/Status(R), `F001`=TxData(W)/RxData(R); A0→RS; Enable=Φ2; `IRQ`→MPU `IRQ`; `RTS` low = paper-tape reader ON), the **34702 baud generator** (2.4576 MHz, 4 jumper holes, ⚠ output **16×** baud), and the **Baudot interface at `F002`** (ACIA unused, MPU bit-bangs 5-level via `BD0`; also the config-bit read port). ⚠ **This resolves the Programming Manual's "address not given" caveat** — the base machine's own serial port *is* `F000`/`F001`; the KCACR `F010`/`F011` and UI/O S9 window are the plug-in boards. Also records the manual's own **page-15 erratum** (the R/W vs R/W-P scope photos are cross-labelled). |
| [Altair 680b Turnkey Front Panel](Altair%20680b%20Turnkey%20Front%20Panel%20Schematic.md) | The single-sheet schematic (MITS DWG **SH 1-11**) for the 680b's **turnkey** front panel — the *reduced* panel a turnkey machine ships with **instead of** the Operator's-Manual hex panel. **No address/data toggles, no DEPOSIT/EXAMINE, no A0–A15 / D0–D7 LEDs** — it only **RESET**s the 6800 and puts it in **RUN or HALT**, with three indicator LEDs (**PWR ON / RUN / HALT**). The emulation payload is the two bus-visible signals, both **debounced and Φ2-synchronized** (a 7474 flip-flop chain clocked by Φ2 on pin 57): **`RES̄`** (connector pin **54**, **active-low** → 6800 RESET → PC from `FFFE/FFFF`) and **RUN/HALT** (pin **63** → 6800 HALT: hi = RUN, lo = halted → `BA` → buses tri-stated). Documents the **reset-scope jumper** (**JA–JC** = reset in Run *or* Halt; **JB–JC** = reset in Halt *only*) as a power-on build constant, the switch/LED complement, the debounce/latch build detail (7474×2 + 7400; R5 20 K / R6 10 Ω / C1 0.1 µF reset debounce; cross-coupled NAND RUN/HALT latch), and power/ground pins (VCC 1/51, GRD 50/100). ⚠ **No boot PROM** — unlike the 8800b Turnkey Module, the reset vector still points into the **main-board** monitor PROM at `FF00`; and ⚠ this panel has **no deposit path**, so HALT here only stops the CPU (the full hex panel's HALT-enables-deposit behavior does not apply). |
| [Altair 680b Software](Altair%20680b%20Software.md) | **Not a hardware manual** — the provenance anchor for the 680b *software* that ships as built-in ROMs. Records the four deramp.com `altair_680/` software directories and what each holds: `PROM Monitor/` (**MON680**, **SWIMON** → `builtin:mon680`/`swimon`), `PROM for KCACR/` (**KCACR** loader/punch → `builtin:kcacr`), `Cassette Binary Loader/` and `BASIC/` (runtime cassette software, not embedded). Notes which images are tracked verbatim under `roms/<NAME>/` (with `.ASM`/`.LST`) and CRC-checked at build time, and which are loaded at run time as on real hardware. Cross-references `docs/roms.md` for the per-image size/range/CRC. |

## SWTPC 6800 boards

The core SWTPC 6800 system boards — the target hardware of this simulator. Like the Altair 680,
these are **memory-mapped 6800** boards (no `IN`/`OUT`).

| Reference | What it covers |
|---|---|
| [SWTPC MP-A 6800 CPU Board](MP-A%206800%20CPU%20Board.md) | The primary logic board: **MC6800** MPU, the **MC6830L7** ROM holding the **MIKBUG** mini-OS (**`E000`–`E1FF`**, lower 512 words only), the **MC6810** 128-byte scratch RAM (the **`A000`–`A07F`** region diagnostics load into), the **MC14411** baud generator (110/150/300/600/1200; control 110/300), the **555** power-up/manual RESET, DMA halt, bus buffers, and the **1.7971 MHz** crystal. The emulation payload is the memory map and the **MIKBUG entry points** (`INEEE`=`$E1AC`, `PDATA1`=`$E07E`, `OUTEEE`=`$E1D1`). ⚠ the assembly manual does **not** describe `FFF8`–`FFFF` vector decode — confirm before assuming. Directory also holds the schematic, SWTBUG/FLEX mods, and Engineering Note 100. |
| [SWTPC MP-A2 6800 CPU Board](MP-A2%206800%20CPU%20Board.md) | The second-generation processor board (circa 1978), superseding the MP-A: same **MC6800** MPU / MC6830 monitor ROM / MC6810 scratchpad / MC14411 baud generator, but built for **2716 EPROMs** (four 2 K sockets, IC23–IC26, relocatable), **MIKBUG-or-SWTBUG** switch-selectable via DIP **S1**, dual +5 regulators, adjustable clock, and external-memory selects above 40 K. The emulation payload is the **two crystals** — **1.7971 MHz for MIKBUG, 1.8432 MHz for SWTBUG** (E-clock ≈ 0.899 / 0.922 MHz) — and the PROM windows (**LOW PROM `C000`**, the target of SWTBUG's `Z`; **HIGH PROM `E000`–`FFFF`** for a custom monitor carrying its own vectors). ⚠ no RAM above 56 K. |
| [SWTPC MP-09 6809 CPU Board](MP-09%206809%20CPU%20Board.md) | The **6809** processor board (circa 1980) that replaces the MP-A/MP-A2: **MC6809** (1 or 2 MHz from a 4 or 8 MHz crystal), the **S-BUG** monitor in IC4 at **`F800`–`FFFF`**, and the **DAT** — a 4-bit × 16 74S189, **write-only at `FFF0`–`FFFF`**, loaded with the *complement* of the physical A12–A15 for each logical 4K segment, so the CPU's logical address becomes a physical one on the bus. The standard 56K map (RAM `0000`–`DFFF`, **I/O moved to `E000`**, DMAF at `F000`), the ROM sockets (decoded on the physical address), the straps, and the FIRQ/NMI/M.RDY lines. ⚠ The `FFxx` DAT bypass at reset is inferred from S-BUG, and says so. |
| [SWTPC MP-S Serial Interface](MP-S%20Serial%20Interface.md) | The standard single-**6850 ACIA** serial board (the console usually attaches here). **Four addresses per I/O slot based at `$8000`** (port N = `$8000+N*4`); the ACIA has a **single register-select pin wired to A0**, so A1 is ignored and the block's **upper two addresses mirror the lower two** — control(W)/status(R) at `base`/`base+2`, Tx(W)/Rx(R) data at `base+1`/`base+3`. So a console in port 1 answers control/status at `$8004` (and `$8006`) and data at `$8005` (and `$8007`). ⚠ **The mirror is load-bearing** — SWTBUG's console probe compares `[$8004]` with `[$8006]` to recognize the ACIA; decode only `$8004`/`$8005` and the monitor never resets it. **110–9600 baud**, **RS-232C *and* 20 mA TTY** (no Baudot); RTS doubles as TTY **reader control**; clock out ≈**16× baud**; solder-jumper `I`→`IRQ` for maskable interrupts. 6850 bit model in [6850](6850.md). |
| [SWTPC MP-S2 Dual Serial Interface](MP-S2%20Dual%20Serial%20Interface.md) | The later **dual-6850** board for the **S/09** (16 addresses per slot). Base **`$E000 + slot*0x10`**; offsets **`+0`/`+1`** = PORT A status/control + data, **`+4`/`+5`** = PORT B, **`+E`/`+F`** = the read-only **Control Line Input Register** (bit0/bit1 = PORT A/B HOLD-DWN, rest reserved); all other offsets **not decoded**. **RS-232C only** (no TTY); per-port **TCLOCK/RCLOCK** jumpers with an **EXT** 16× external-clock position (CT-82); **CTS** flow control (high = send at baud÷10, low = inhibit, no loss); both `IRQ`s hardwired to system IRQ. Second port added by the **MP-SX** kit. |
| [SWTPC MP-C Serial Control Interface](MP-C%20Serial%20Control%20Interface.md) | The **control interface** — the serial terminal board that occupies **I/O port 1** (`8004`–`8007`) and the one [MIKBUG](MIKBUG%20Monitor.md) was written for. Built around an **MC6820 PIA** (not an ACIA): the monitor **bit-bangs** the serial line through PIA bits in software-timed loops. Fills all four port addresses as two PIA register pairs (`8004`/`8006` data A/B, `8005`/`8007` control A/B). **110 (10 cps) or 300 (30 cps) baud**, RS-232C or 20 mA TTY (ASCII only); CO ≈16× baud (1758.8 / 4800 Hz); same 10-pin connector as the MP-S. ⚠ **swtpcsim ships no MP-C** — a faithful PIA console is a CPU-timing-dependent software UART, so `swtpc` boots SWTBUG on an MP-S ACIA instead (SWTBUG can still detect either). |
| [SWTPC AC-30 Cassette Interface](AC-30%20Cassette%20Interface.md) | The audio-cassette interface (Kansas City, **300 baud**), sitting between the CT-1024 terminal and the 6800 — **not memory-mapped**: commanded by **ASCII device-control characters sent through the terminal** (**`$11`** DC1 = record/read ON, **`$14`** DC4/Ctrl-T = record OFF), with read echo suppressed via `STA $8007`. Contents are the three **diagnostics** — **TAPWRT-1** (test-tape generator; delay const `A01B`, NOP-patch `A01C`/`A01D` for continuous), **TAPRED-1** (read/verify, `/`=good `X`=bad), **FIVPNT-1** (ASCII-`5` calibration tape, trim **R16**) — all loading into MIKBUG scratch RAM (`A000`–`A07F`) and calling `OUTEEE`/`INEEE`/`PDATA1`. Contrast the memory-mapped [Altair 680b KCACR](Altair%20680b%20KCACR.md). |
| [SS-50 / SS-30 Bus](SS-50%20SS-30%20Bus.md) | The two SWTPC buses (from the **MP-B** motherboard): the **SS-50** 50-line system bus (CPU + up to 32 K RAM) and the **SS-30** 30-line I/O bus (eight interface slots). The emulation payload is the **memory map** (RAM `0000`–`7FFF`, I/O `8000`–`801F`, scratchpad `A000`–`A07F`, monitor `E000`–`E1FF`/`E3FF`, restart mirror `FFF8`–`FFFF`) and the **per-slot decode**: each SS-30 port is **four addresses** (`8000 + N·4`), **port 1 = `8004`–`8007` is the control/console slot**, and the slot's register selects are **`RS0`=A0, `RS1`=A1** — the root of the MP-S ACIA's one-bit-select mirror. Active-low bus signals (`D0`–`D7`, `NMI`, `IRQ`, `Φ2`, `VMA`, `R/W`, `RESET`, `HALT`), five baud clocks, ±12 V for line drivers. ⚠ nothing may sit above the monitor ROM (it owns the restart mirror). |

## Monitor firmware

The ROM-resident **mini-operating systems** of the SWTPC 6800 — the `$`/`*` prompt a machine comes
up to. Documented here as references (entry points, memory map, boot behavior); the images
themselves are embedded ROMs (`docs/roms.md`).

| Reference | What it covers |
|---|---|
| [SWTBUG Monitor](SWTBUG%20Monitor.md) | SWTPC's **1977** monitor (v1.0), the firmware `machines/swtpc.toml` boots (as `builtin:swtbug`) — a **1 KB** ROM at **`E000`–`E3FF`** with 128-byte scratchpad at **`A000`–`A07F`** and vectors in-ROM at **`E3F8`–`E3FF`** (RESET → **`START`=`E0D0`**). The emulation payload: the memory footprint, the vector table (IRQ/SWI/NMI indirect through `[A000]`/`[A012]`/`[A006]`), the **one-letter commands** (`M`/`R`/`G`/`J`/`L`/`P`/`E`/`B`/`C`/`D`/`F`/`O`/`Z`), the scratchpad variable map, and the **MIKBUG-compatible entry points** (`INEEE`=`E1AC`, `OUTEEE`=`E1D1`, `PDATA1`=`E07E`, `CONTRL`=`E0E3`). ⚠ the `$` prompt depends on the ACIA-mirror probe; ⚠ boot from `E0D0` under `--mcp`; ⚠ `D` boots an MF-68 (not the DC-4). |
| [S-BUG Monitor](S-BUG%20Monitor.md) | The **6809** monitor (**S-BUG 1.8**) in the MP-09's IC4 — a **2 KB** ROM at **`F800`–`FFFF`**, reset at **`FF00`**. Its reset loads the DAT, finds and maps RAM (`$55AA` probe, the `LRARAM` table), and signs on `S-BUG 1.8 - 56K` with a **`>`** prompt; RAM at **`DFC0`–`DFFF`**; console **MP-S at `E004`**; the `F800` entry table; the command set; and the **`U` minifloppy boot** (DC-x `E014`/`E018`, track 0 sector 1 → `C000`) FLEX9 comes up through. ⚠ Source line 383 merges two instructions. |
| [MIKBUG Monitor](MIKBUG%20Monitor.md) | Motorola's original 6800 monitor (**MCM6830L7**, Rev 9, ©1974), the ancestor SWTBUG replaced and the source of the shared entry-point addresses. Three programs in one ROM: **MIKBUG Rev 9** (`E000`–`E1FF`), **MINIBUG Rev 4** (`FE00`–`FEFF`, UART-based), and a **Test Pattern** (`EE00`–`EEFF`); PIA console at **`8004`–`8007`**; prompt `*`; commands `L`/`M`/`R`/`P`/`G` (⚠ the source comment says `F` for punch but the code matches `P`). ⚠ **swtpcsim ships SWTBUG, not MIKBUG** — MIKBUG bit-bangs the serial line through the MP-C PIA with CPU-timing-dependent delay loops, which the free-running emulator does not reproduce. |
